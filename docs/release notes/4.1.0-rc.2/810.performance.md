### Faster In-Memory Graph Search

**Description**

`GraphSearcher` handled each scored neighbor in a callback that the graph view called once per neighbor. Search was
fast only when the JIT inlined that callback into the view, which depended on the order in which the two were
compiled, so speed varied between runs and code changes. The view now only collects each expansion's neighbors and
scores, and `GraphSearcher` handles them in its own loop. Searches over in-memory vectors are up to about 35% faster
with small vectors (about 17% at 128 dimensions); the gain shrinks as dimensions grow and is within noise at 3,072
dimensions and on compressed or on-disk paths. A search also allocates less, because the `visited::add` marker is now
created once per searcher instead of once per expanded node (see [#809](https://github.com/datastax/jvector/issues/809)).
Results are unchanged.

**How to Enable**

No configuration is required.
