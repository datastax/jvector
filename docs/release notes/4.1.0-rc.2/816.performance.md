### Faster PQ Query Setup for COSINE and DOT_PRODUCT on 128-bit SIMD

**Description**

`PanamaVectorUtilSupport.dotProduct(v1, off1, v2, off2, length)` sent every slice of at least one vector through
`dotProductPreferred`, a method too large for the JIT to inline, even when the slice was exactly one vector wide.
That is the usual PQ subvector size on 128-bit hardware (4 floats), and building the per-query lookup table calls it
once per centroid, so `COSINE` and `DOT_PRODUCT` tables took 7 to 11 times as long as `EUCLIDEAN` ones. The exact-fit
case is now handled before delegating. Results are bit-identical. See
[#815](https://github.com/datastax/jvector/issues/815).

**How to Enable**

No configuration is required.

**Notes**

On Apple silicon, building the PQ table for a 1024-dimension, 256-subspace index dropped from 281 to 24 microseconds
for `COSINE` and from 167 to 24 for `DOT_PRODUCT` (`EUCLIDEAN` was already 24.5). Fused-PQ cosine search from disk
over 30,000 vectors went from about 1,720 to about 2,630 queries per second on one thread. x86 was not measured.
