### Avoid False Sharing Between Concurrent Graph Searches

**Description**

With several searchers running concurrently, some JVMs ran graph search about 15% slower for their whole lifetime.
For every scored neighbor, `GraphSearcher` read shared objects (`Bits.ALL` and the no-op score tracker) and wrote
its own visit counter. When one searcher was placed on the same cache line as a shared object, its writes slowed
every other searcher. The search now checks for an accept-all filter and a no-op tracker once per layer, and
counts visits locally, adding them once per layer. Results and visit counts are unchanged.

**How to Enable**

No configuration is required.
