### Resumed Searches Return Nodes Tied at the Cutoff

**Description**

When a search's `rerankK` results were full, a node that scored exactly the same as the worst result was neither
kept in the results nor saved for `GraphSearcher.resume()`, so no later resume could return it. Exact ties are common
with duplicate vectors, with COSINE and vectors that point the same way, and with quantized scores, so resuming
until no results remain could silently miss nodes. Such nodes are now saved, and a resume returns them. With adaptive
stopping enabled, nodes expanded below the cutoff are saved the same way. Results of `search()` itself are unchanged.

**How to Enable**

No configuration is required.

**Notes**

Fixes [#844](https://github.com/datastax/jvector/issues/844).
