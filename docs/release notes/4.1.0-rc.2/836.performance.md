### Native Provider No Longer Slows Down on Small Vectors and PQ Subspaces

**Description**

The native provider made many tiny native calls on small vectors and PQ subspaces, where each call
costs more than the math it does. Building a 128-dimension graph with PQ in 2-float subspaces ran
about 2x slower on native than on Panama.

- PQ diversity scoring now compares two codes straight from the codebooks, in one pass per
  comparison, for both in-progress and saved PQ vectors. It replaces the per-subspace calls and the
  centroid-pair table (except for subspaces of 16 floats or more; see 850), which held `subspaces × 256 × 257 / 2`
  floats (17 MB at 128 subspaces) and was slow on Panama. Otherwise its only memory is one copy of
  the codebooks, made on first use.
- k-means++ initialization computes distances in Java for subspace sizes the native update doesn't
  handle.
- Native f32 similarity calls no longer create and cache a view for each freshly read vector, and
  native vectors cache their view without locking.

Native builds are now as fast as Panama or faster, with no dimension threshold.

**How to Enable**

No configuration is required.
