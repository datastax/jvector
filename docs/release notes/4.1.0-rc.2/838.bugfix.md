### PQ Encoding No Longer Falls Back to the Vector API's Java Path on JDK 21

**Description**

On JDK 21, `ProductQuantization.encodeAll` could run the Vector API's Java fallback instead of SIMD, 17–30× slower
per centroid distance, depending on the order a fresh JVM compiled its methods in. `VectorAccess.forEach` called the
consumer once per vector from `IntStream.forEach`, so C2 could compile the JDK stream frame with the encode inlined
beneath it, past its inlining limit. Point-access scans now have each worker claim 16-position chunks and loop over
them, so the encode is compiled on its own. The Panama provider also implements `tryClosestCentroid` for subspaces of up
to three floats, such as Apache Cassandra's 2-float subspaces, with a scalar scan that leaves the Vector API out of the
encode. Codes are unchanged. See [#801](https://github.com/datastax/jvector/issues/801).

**How to Enable**

No configuration is required.

**Notes**

With 2- and 3-float subspaces, the scalar scan is a few percent slower than SIMD in a JVM where SIMD would have
worked. `VectorUtilSupport` gains a default method, `closestCentroidChecksFiniteness`, which lets a provider whose scan
checks distances itself skip `VectorUtil`'s second finiteness scan under `-ea`.
