### `GraphIndexBuilder` Closes the Per-Thread Vector Copies It Creates

**Description**

For a shared `RandomAccessVectorValues` (one that reuses a buffer, such as a file-backed source),
`threadLocalSupplier()` hands each thread its own `copy()`, but nothing could close those copies, so `AutoCloseable`
copies (for example, ones holding a mapped file) stayed open. The supplier for shared sources is now `AutoCloseable`:
closing it closes every `AutoCloseable` copy it created and clears the per-thread cache. `GraphIndexBuilder.build`
and `buildAndMergeNewNodes` close their supplier when construction ends, and only after every parallel worker has
stopped, even if one fails. Copies made by `RemappedRandomAccessVectorValues` now close their copy of the wrapped
source, which is never closed itself. See [#635](https://github.com/datastax/jvector/issues/635).

**How to Enable**

No configuration is required.

**Notes**

Code that calls `threadLocalSupplier()` itself can close the returned supplier when it is an `AutoCloseable` to
release its copies; the supplier stays usable afterwards and makes new copies on demand. Un-shared sources still get a
supplier that returns the source itself. Copies held by the exact-scoring build score providers are not yet closed;
that is tracked in [#764](https://github.com/datastax/jvector/issues/764).
