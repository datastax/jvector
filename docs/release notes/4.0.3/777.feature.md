### Compaction for hosts that own their storage

**Description**
`OnDiskGraphIndexCompactor` can now be used as the merge step of a system that keeps
vectors and graphs in its own storage (for example tiered graphs in a database), with
three opt-in additions (#775):

* **Caller-supplied vectors**: a constructor taking one `RandomAccessVectorValues` per
  source. Sources may be topology-only (`InlineVectors` of dimension 0); every vector
  the merge reads comes from the caller, and only live ordinals are requested.
* **Caller-provided output**: `compact(IndexWriter, Path)` and
  `compact(IndexWriter, IndexWriter, Path)` write the compacted graph (and its compressed
  sidecar) sequentially to the caller's `IndexWriter`, keeping scratch and spill files
  in the given work directory.
* **Caller-chosen output ordinals**: `withOutputOrdinals(List<int[]>)` writes the graph
  in the caller's ordinal order, so no renumbering pass is needed afterwards.

**How to Enable**
No configuration is required. The existing constructors, `compact(Path)` and
`compact(Path, Path)` are unchanged; the new constructor and methods are used only when
called. See [compaction](../../compaction.md).

**Notes**
Also fixes a leaked reverse-offer spill directory when a compaction fails.
