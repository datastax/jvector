### Modular Benchmark Harness: Grid Refactor for BenchYAML and AutoBenchYAML

**Description**
`Grid`, the engine behind `BenchYAML` and `AutoBenchYAML`, was refactored so that each benchmarking initiative can put its changes in its own files. Almost every core change also changed `Grid.java`, and with several initiatives in flight at once it had merge conflicts at nearly every release. The class is now a small orchestrator (692 lines, down from 1,395). Its extension points live in separate files in `io.github.jbellis.jvector.example`:

| Concern | Before | Now |
|---|---|---|
| Two pipelines | `runAll` and `runAllAndCollectResults` were near-copies | One pipeline; AutoBenchYAML adds a result collector |
| Build parameters | 5–7 positional arguments threaded through every method | `BuildConfig` (one build point) and `SearchConfig` (the search sweep) |
| Construction sweep | Six hand-nested `for` loops | `GridSpec` with ordered `SweepDimension`s; `GridSpec.fromConfig(MultiConfig)` maps the YAML |
| Graph construction | Inline `buildInMemory` / `buildOnDisk` | `IndexBuildStrategy`: `InMemoryBuild`, `CompressedOnDiskBuild` (includes the index cache) |
| Core builder/writer calls | Spread through Grid | `GraphBuilderFactory` only |
| On-disk features | A `switch` on `FeatureId` plus `FUSED_PQ` checks in five other places | `FeatureProvider` per feature (`InlineVectorsProvider`, `NVQProvider`, `FusedPQProvider`), registered in `FeatureProviders` |
| Console, experiments.csv, AutoBench results | Inline in `testConfiguration` | `GridListener`s: `ConsoleReportListener`, `ExperimentsLogListener`, `BenchResultCollector` |
| Reported build parameters | Listed separately by each output | `BuildConfig.reportedParameters()` |

Each step was checked against the previous code on `lastfm-64-dot` by comparing `experiments.csv` rows, AutoBench `BenchResult` output, console tables, and the builds, cache hits and skip messages logged. Output matched except for the changes listed below.

**How to Enable**
No configuration is required. Command lines, dataset YAML files (`yaml-configs/index-parameters/`), `run-config.yml`, and the experiments.csv schema (v1) are unchanged.

**Running BenchYAML: what changes**

- **Unchanged:** command line, YAML configs, `run-config.yml` selections, experiments.csv columns and values, console table columns.
- **Feature-set order is stable.** Indexes are searched in the configured order. That is the `reranking` list order, with each `fusedGraph` value producing a full pass over it, e.g. `reranking: [NVQ, FP]` gives NVQ then FP. Previously the order of console blocks and experiments.csv rows changed between runs, because `EnumSet` hash codes come from identity hashes.
- **No stale search timings on fused rows.** Fused-PQ indexes skip search compression, but they could report the previous index's `Search PQ encoding (s)`. They no longer do.
- **Clearer errors for incomplete configs.** A missing construction sweep field fails with its name, e.g. `No values to sweep for outDegree` or `construction.useSavedIndexIfExists must be set`, instead of a bare `NullPointerException`. The whole sweep is validated before the first build.
- **Feature checks run before any file is written.** "Bench looks for either NVQ_VECTORS or INLINE_VECTORS feature set for scoring compressed builds" and "FusedPQ requires PQ build compression with 256 clusters" now fail before any index writer is opened, so a failed run no longer leaves partial index files.
- **Console messages.** In-memory builds now print `Skipping [INLINE_VECTORS, FUSED_PQ] when building in memory: it needs a compressed build`. A feature set containing a feature Grid cannot write (e.g. `SEPARATED_VECTORS`) prints `Skipping <id>: Grid has no FeatureProvider for it`; previously it was dropped silently.

**Running AutoBenchYAML: what changes**

AutoBenchYAML now runs through the same pipeline as BenchYAML. Its command line (`--output`, `--config`, `--diag`, dataset patterns), output files (`<output>.csv`, `<output>.json`, checkpoint), and fixed regression benchmark set are unchanged.

- **One graph per build configuration.** Each feature set is still written to, and searched in, its own index file. The difference is that the old path rebuilt the graph and rewrote every feature set's file for each feature set and each search compressor, then searched only one of them. With F feature sets and S search compressors (index cache off), it did F × S graph builds and F × F × S file writes; it now does 1 and F. The graph does not depend on the feature set (compressed builds score with the PQ/BQ build vectors), and search compression is not stored in the index, so the repeats only produced more random graphs with the same parameters.
- **Results to expect when comparing against an earlier run:**
  - **CSV columns unchanged; Build Heap / Build Off-Heap values shift.** The build memory snapshot is now taken right after the build, before search vectors are encoded. Expect one comparison cycle where these move.
  - **Index Build Time.** On earlier code this was the last of the redundant builds, each doing the same work as the single build now, so values are comparable with less run-to-run noise.
  - **Within a build config, INLINE and NVQ rows search the same graph.** Comparisons between feature sets then differ only in stored features and reranking, and `Avg Visited` matches between them.
  - **Total run time drops**, and off-heap memory stays flat because indexes are now closed after use.
- **JSON (`<output>.json`):**
  - **Parameter keys are unchanged.** `buildCompressor` / `searchCompressor` remain lambda `toString()` values, which differ between runs; exclude them when diffing.
  - **Existing metric keys are unchanged.** Construction metrics are added when measured: `Index build time (s)`, `Index file size (MB)`, `Idx PQ compute (s)`, `Idx PQ encoding (s)`, `Idx NVQ compute (s)`, `Search PQ compute (s)`, `Search PQ encoding (s)`. `BenchmarkSummarizer` does not read these, so the CSV is unaffected.
  - **Rows follow the configured feature-set order.**
- **Console.** AutoBenchYAML now prints the same per-configuration tables as BenchYAML.
- **Checkpoints.** The `BenchResult` format is unchanged, so a checkpoint from an earlier build can be resumed. Datasets completed before the upgrade keep their earlier metrics (no construction metrics, earlier memory snapshot timing).

**Updating the harnesses**

Entry points (all callers in the repository have been migrated):

```java
// BenchYAML, HelloVectorWorld
Grid.run(ds, GridSpec.fromConfig(config), artifacts);

// AutoBenchYAML
List<BenchResult> results = Grid.runAndCollectResults(ds, GridSpec.fromConfig(config));
```

| To add | Change |
|---|---|
| A construction parameter | A field and builder setter **with a default** in `BuildConfig`; its use, usually in `GraphBuilderFactory`; its field in `ConstructionParameters`. If swept, one `sweep(...)` line in `GridSpec.fromConfig`. To report it, one line in `BuildConfig.reportedParameters()` (it then appears in the console config block and AutoBench JSON params). |
| An experiments.csv column for it | Its name in `ExperimentsSchemaV1.BUILD_PARAMETER_COLUMNS`. This changes the versioned CSV schema, so it is deliberate, not automatic. |
| A search parameter | A field and builder setter in `SearchConfig`, and its loop in `Grid.testConfiguration`. |
| An on-disk feature | A new `FeatureProvider` file and one `register(...)` line in `FeatureProviders`. |
| A report or output format | A new `GridListener` file and one line where the entry point builds its listener list (`Grid.reportingListeners` or `Grid.runAndCollectResults`). |
| Data for listeners | A field on `SearchContext`, set where `Grid.runOneGraph` creates it. |

Example: a new swept construction parameter `myKnob`:

```java
// BuildConfig: field, constructor assignment, and a builder setter with a default
public final int myKnob;
private int myKnob = 4;
public Builder myKnob(int myKnob) { this.myKnob = myKnob; return this; }

// ConstructionParameters: the YAML field
public List<Integer> myKnob;

// GridSpec.fromConfig: sweep it. The position in the chain sets its place in the output order;
// SweepDimension rejects a null list, so default it if the YAML field is optional.
.sweep("myKnob", construction.myKnob, BuildConfig.Builder::myKnob)

// BuildConfig.reportedParameters(): show it in console and JSON results
params.put("myKnob", myKnob);

// GraphBuilderFactory: pass build.myKnob to the core builder
```

Example: a new on-disk feature:

```java
final class MyFeatureProvider implements FeatureProvider {
    public FeatureId id() { return FeatureId.MY_FEATURE; }
    public void configure(FeatureWriteContext ctx) {
        ctx.add(new MyFeature(ctx.vectors().dimension()));
        ctx.supplyFromVector(FeatureId.MY_FEATURE, vector -> new MyFeature.State(vector));
    }
    // Override supportsInMemoryBuild, providesRerankVectors, providesApproximateScoring or
    // checkCompressedBuild if the defaults do not fit.
}
// FeatureProviders: register(new MyFeatureProvider());
```

**Porting in-flight branches that changed Grid**

| Old location in `Grid.java` | New location |
|---|---|
| `runAll(...)` overloads | Removed (package-private); use `Grid.run(ds, spec, artifacts)` |
| Sweep loops in `runAll` / `runAllAndCollectResults` | `GridSpec.fromConfig` and `GridSpec.buildPoints()` |
| `runAllAndCollectResults` body | `Grid.runAndCollectResults`; the old method is a `@Deprecated` adapter |
| `buildInMemory` | `InMemoryBuild` |
| `buildOnDisk`, `writeInlineStates`, index-cache lookup in `runOneGraph` | `CompressedOnDiskBuild` |
| `new GraphIndexBuilder(...)`, `BuildScoreProvider.*`, writer builder setup | `GraphBuilderFactory` |
| `builderWithSuppliers` `switch` cases | `InlineVectorsProvider`, `NVQProvider`, `FusedPQProvider` |
| `FUSED_PQ` / `INLINE_VECTORS` / `NVQ_VECTORS` checks | `FeatureProvider` hooks |
| Console table code in `testConfiguration` | `ConsoleReportListener` |
| `artifacts.logRow(...)` in `testConfiguration` | `ExperimentsLogListener` |
| `BenchResult` construction for AutoBench | `BenchResultCollector` |
| `ConstructionMetrics`, `FinalWriteVectors` (nested classes) | Their own files, unchanged |
| AutoBench benchmark list | `Grid.regressionBenchmarks()` |

Deprecated, still working: `Grid.runAllAndCollectResults(...)`, the positional `RunArtifacts.logRow(...)`, and the positional `ExperimentsSchemaV1.fixedValues(...)`. Use `Grid.runAndCollectResults`, and the overloads that take the build parameters as a map. `Grid.runOneGraph(...)` keeps its signature for the tests that call it.

**Notes**
- Used internally by JVector benchmarking, no client impact. No core library code changed.
- `TestBufferedGraphCompatibility` now compares search scores within `1e-6`. Panama's float reductions round differently before and after C2 compiles them, which made the test fail intermittently on machines without the native vector library (all macOS machines). CI builds the native library, so it was not affected.
- New tests: `TestGridSpec` (sweep order against the old loop nest, empty and missing dimensions, YAML mapping) and `TestReportedParameters` (reported parameter names and order, experiments.csv columns).
