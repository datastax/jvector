### Deferred batch graph serialization

Parallel graph serialization can now write complete layer-zero records in bounded
batches of 64, with an optional positive batch-size override. When the parallel writer
is selected, Grid supplies inline NVQ or full-precision features during final
serialization, after graph cleanup, and uses buffered vector ranges when the input
source supports them. With the sequential writer selected, Grid keeps encoding those
features during insertion.

The core writer accepts application-supplied feature states independently of the
benchmark harness or dataset prefetching. Complete-record batching applies equally
to fully preloaded inputs; the source does not have to preload the whole dataset.

Integrators should use the parallel writer when deferring NVQ/FP encoding to
final serialization. A sequential final writer performs that encoding on one
thread and can regress construction time. Sequential callers should retain
encoding during insertion and `writeFeaturesInline`.

The existing V6 layout, readers, ordinary vector sources, and incremental
`writeFeaturesInline` API remain supported. Prewritten features are preserved.
Concurrent feature suppliers must keep their input source available until writing
finishes. BenchYAML and AutoBenchYAML default to parallel writing, with
`-Djvector.parallel_writer=false` selecting the sequential path. The library
writer default remains unchanged.

Recorded construction studies with dataset prefetching reduced ample-memory final
write time from 136.10 to 50.69 seconds on MPNet 10M, 148.50 to 64.02 seconds on
Cohere 10M, and 162.64 to 51.76 seconds on CAP 6M.[^machine] These are separate fresh runs,
not a universal throughput or memory guarantee. See
[Deferred batch serialization](../../deferred-batch-writer.md) for usage.

Construction tutorials and examples now demonstrate final feature suppliers for
deferred FP/NVQ writing, with per-worker source views and an explicit source-lifetime
requirement. The query algorithms and quantization settings are unchanged.

[^machine]: GCE VM, 48-core Intel Xeon 6985P-C (96 threads), local SSD RAID10, JDK 23, 128 GiB heap; native Highway, 48 workers.
