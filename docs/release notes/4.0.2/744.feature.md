Added optional batched vector access and a bounded file source for quantizer
training, encoding and existing full-precision/NVQ disk serialization. Capable
algorithms can consume samples or full scans without requiring an upfront preload
of the original base dataset; existing vector sources remain supported.

BenchYAML and AutoBenchYAML support `useDatasetPrefetching: true` in their index
configuration. The flag defaults to false, preserving resident loading and scoring.
Comparison-heavy uncompressed configurations retain resident input. The existing
`jvector.dataset_loader` VM option overrides the flag, while configurations
requiring resident raw vectors still preload; an explicit buffered request logs
the reason for that fallback.

See [batched vector access](../../batched-vector-access.md) for ownership,
resource limits, examples and the benchmark opt-in. Encoded vectors, training
working memory and graph structures retain their existing memory requirements.
