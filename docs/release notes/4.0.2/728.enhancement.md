### Generic Index API and a Simpler Builder for Graph Indexes

**Description**  
Adds a backing-agnostic `Index` API and `HnswIndexBuilder`, a fluent builder for graph indexes that makes the common case one call. Until now every caller assembled the pieces by hand: choosing among `GraphIndexBuilder`'s telescoping constructors, training and encoding PQ themselves to build with compressed scores, wiring writers and feature-state maps to persist a graph, and building score providers to search it. `HnswIndexBuilder` wraps the same `GraphIndexBuilder` code, so a graph built with the same settings is the same graph, built in the same time; what changes is how much the caller has to write.

- **Type-first entry point.** `Indexes.hnswBuilder(vectors, similarityFunction)` or `Indexes.hnswBuilder(scoreProvider, dimension)` picks the index type first, so only graph settings exist on the builder. Every setting has a default (max degree 32, beam width 100, neighbor overflow 1.2, alpha 1.2, hierarchy and final refinement on), and `buildAndPopulate()` builds a complete graph.
- **Compression is a setting.** `withCompressionType(CompressionType.PQ)` or `BQ` makes the builder train the quantizer, encode the vectors and build with compressed scores. PQ training defaults match Cassandra's (code size by dimension, no centering, unweighted) and can be overridden with `withPqSubspaces`, `withPqGlobalCentering` and `withPqAnisotropicThreshold`. `getCompressedVectors()` returns what was trained, ready to search with or to write as a `FusedPQ` feature, so there is no second quantizer to train.
- **Incremental construction on the same builder.** `build()` returns the graph for `addGraphNode` (thread-safe, searchable while it grows), `markNodeDeleted`, `removeDeletedNodes` and `cleanup()`; `HnswIndexBuilder.rescore` re-scores a graph mid-build; `withExistingGraph` continues a graph reloaded with `OnHeapGraphIndex.load`.
- **Generic handles.** `io.github.jbellis.jvector.api.Index` and `IndexSearcher` are backing-agnostic; `GraphIndex` (formerly `ImmutableGraphIndex`) implements `Index`, and `graph.searcher()` returns a `GraphSearcher`.
- **Simpler persistence.** A built graph is a `PersistableGraphIndex` whose accessors return each writer's own builder: `getWriterBuilder(IndexWriter)` (sequential), `getParallelWriterBuilder(Path)` and `getWriterBuilder(Path)` (random access). `writeTo(path, vectors)` writes the simplest on-disk index in one call, and `GraphSearcher.search(query, topK, rerankK, similarityFunction, acceptOrds)` searches an on-disk graph with the vectors it stores, using fused PQ codes when present, with no score provider to build.

**Purpose / Impact**
- Building, compressing, persisting and searching a graph each take a line or two instead of hand-assembled pieces.
- No change in performance or recall: measured against `main` on 100,000 128-dimension vectors, build time, in-memory and on-disk search latency, and recall (exact, inline-vector and fused-PQ) are the same within run-to-run noise.
- Mistakes surface early: null inputs, out-of-range PQ settings, a populate with the wrong vectors, and continuing an existing graph with a different kind of scoring (exact versus compressed) or a conflicting shape are rejected with a clear message. Writer options a writer doesn't support are compile errors.

**How to Enable**  
No configuration is required; the new API is opt-in, and `GraphIndexBuilder` remains fully supported. A complete compressed index, written to disk and searched:

```java
var builder = Indexes.hnswBuilder(vectors, VectorSimilarityFunction.COSINE)
        .withCompressionType(CompressionType.PQ);     // optional
PersistableGraphIndex graph = builder.buildAndPopulate();
PQVectors pq = (PQVectors) builder.getCompressedVectors();

// Persist with inline vectors and fused PQ codes, using the builder's own PQ
try (var view = graph.getView();
     var writer = graph.getWriterBuilder(path)
             .with(new InlineVectors(dimension))
             .with(new FusedPQ(graph.maxDegree(), pq.getCompressor()))
             .build()) {
    var states = new EnumMap<FeatureId, IntFunction<Feature.State>>(FeatureId.class);
    states.put(FeatureId.INLINE_VECTORS, node -> new InlineVectors.State(vectors.getVector(node)));
    states.put(FeatureId.FUSED_PQ, node -> new FusedPQ.State(view, pq, node));
    writer.write(states);
}

// Search the on-disk graph with the vectors it stores
try (var rs = ReaderSupplierFactory.open(path);
     var onDisk = OnDiskGraphIndex.load(rs);
     var searcher = onDisk.searcher()) {
    SearchResult result = searcher.search(query, 10, 30, VectorSimilarityFunction.COSINE, Bits.ALL);
}
```

`jvector-examples/.../IndexApiExample.java` walks through every pattern (fused PQ, NVQ, separately stored PQ codes, incremental construction with deletes, a mid-build PQ rescore, continuing a saved graph) and prints the recall of each. Run it from the project root with `mvn compile exec:exec@index-api-example`. `UPGRADING.md` maps each `GraphIndexBuilder` construction pattern to its `HnswIndexBuilder` equivalent.

**Breaking Changes**
- `ImmutableGraphIndex` is renamed to `GraphIndex`, with no deprecated alias; its nested types (`View`, `ScoringView`, `NodeAtLevel`, ...) and `prettyPrint` move with it. The rename is mechanical.
- `GraphIndexBuilder.build(RandomAccessVectorValues)` and `getGraph()` return `PersistableGraphIndex` (a `GraphIndex`); `buildAndMergeNewNodes` returns `GraphIndex`. Code assigning these to `GraphIndex` compiles unchanged.
- Recompile against 4.0.2: classes compiled against 4.0.1 that use the renamed types will fail to link.

**Behavior Changes and Fixes**
- Adding nodes to an `OnHeapGraphIndex` after `cleanup()` now works correctly; previously a later insert could link a node to itself and concurrent searches could see half-inserted nodes.
- `GraphIndexBuilder.rescore` now keeps nodes marked deleted but not yet removed; previously they became visible to searches again and survived `cleanup()`.
- Writer builders given a `Path` now open the file in `build()` rather than in the constructor, so an abandoned or failed builder no longer leaks a file handle; an error opening the file is thrown by `build()`.
- The PQ training error for too few vectors now reports the cluster and vector counts.

**Notes**
- `HnswRecipe` / `IvfRecipe` (`applyRecipe`) and the IVF types (`Indexes.ivfBuilder()`, `IvfIndexBuilder`, `IvfIndex`, `IvfSearcher`) are `@Experimental` placeholders: only `HnswRecipe.DEFAULT` is defined, and IVF refuses to build until it is implemented.
- `HnswIndexBuilder` takes its settings explicitly rather than from the JMX `GraphIndexBuilderConfig` (only the PQ cluster count, 256, still comes from it).
- Concurrency is the same as `GraphIndexBuilder`: inserts and deletes are thread-safe, while `cleanup()`, `removeDeletedNodes()`, `rescore` and `close()` must not run during inserts. Reuse a searcher per thread rather than creating one per search; for a growing in-memory graph, refresh it with `setView(graph.getView())`.
- Design history and remaining open items (a generic `search` on `IndexSearcher`, JMX integration, typed recipe values) are in `design-notes/index_hierarchy_plan.md`.
