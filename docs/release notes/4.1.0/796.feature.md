### Asymmetric Scalar Hashing (ASH) quantization

**Description**

JVector adds ASH (Asymmetric Scalar Hashing), introduced in
[ASH: Asymmetric Scalar Hashing With Learned Dimensionality Reduction for High-Fidelity Vector Quantization](https://arxiv.org/abs/2606.07870)
(Tepper and Willke, CIKM 2026). ASH is a data-driven encoder-decoder framework that applies
dimensionality reduction to database vectors via a learned orthonormal projection, followed by
scalar quantization, while keeping queries in their original form. This asymmetric design enables
higher accuracy than the best additive and scalar quantizers at iso-compression, while admitting
highly efficient similarity computations via SIMD operations. ASH has short learning and encoding
times, making it attractive for real-world deployment.

This release brings ASH to a graph index for the first time. JVector stores each projected
dimension in 1 to 4 bits (up to 9 outside fused graphs), projects each query once, and scores it
against the stored codes with SIMD lookups. [ASH performance](../../ash-performance.md) compares
ASH with product quantization (PQ) in JVector graphs on 6M and 10M datasets.

JVector supports ASH wherever it supports PQ:

- **Training and encoding.** `AsymmetricHashing.initialize` trains a model with an ITQ-learned or
  random projection, a number of landmarks, and a chosen bit budget. `encodeAll` produces
  `ASHVectors`, which implement `CompressedVectors` and keep all codes in compact shared pages.
  The quantizer accepts 1 to 256 landmarks; JVector's graph indexes currently use one.
- **In-memory graphs.** `ASHVectors` score graph construction and search like other compressed
  vectors. `BuildScoreProvider.ashBuildScoreProvider` builds the graph by comparing stored codes
  with each other (symmetric scoring), so insertion needs no full-precision query projection.
- **Fused ASH on disk.** The `FusedASH` feature (`FeatureId.FUSED_ASH`) stores each node's
  neighbors' ASH codes with its adjacency list and the model in the index header, so on-disk
  search reads no separate code file. Fused ASH supports 1, 2 and 4 bits per dimension and
  reranks with NVQ or full-precision vectors stored in the graph.
- **Separate ASH codes.** An on-disk graph with full-precision vectors can be searched with
  `ASHVectors` held in memory, as with PQ.
- **Native query projection.** With the native vectorization provider, queries are projected in
  FP16 where the CPU supports it, falling back to FP32. INT8 projection is available on request
  for x86 processors with VNNI or AMX. Native builds include the oneDNN projection engine by
  default; base-vector encoding uses FP32.
- **Prepared and queued queries.** Each ASH query is projected once before its graph search, and
  projecting several queries together in one matrix multiply costs less per query than projecting
  them one at a time. `QueryPreparer` and `PreparedQuery` therefore separate projection from graph
  search, and `BatchingExecutor` queues concurrent searches on host-owned workers with bounded
  admission so that queries waiting at the same time share one batched projection. Concurrent
  synchronous searches also share projections, up to `jvector.ash.queryBatchSize` (default 8).

**How to Enable**

ASH is opt-in; existing PQ, BQ and NVQ indexes and their defaults are unchanged. A fused ASH index
with NVQ reranking is built and searched as follows; the complete program is
[HelloASHWorldFp16](../../../jvector-examples/src/main/java/io/github/jbellis/jvector/example/HelloASHWorldFp16.java).

```java
int b = 2, d = dimension / 2;   // 2 bits for each of D/2 projected dimensions
var ash = AsymmetricHashing.initialize(vectors, AsymmetricHashing.ITQ,
        AsymmetricHashing.HEADER_BITS + b * d, 1, b, PhysicalCoreExecutor.pool());
var codes = ash.encodeAll(vectors, PhysicalCoreExecutor.pool());
var scores = BuildScoreProvider.ashBuildScoreProvider(VectorSimilarityFunction.DOT_PRODUCT, codes);
// Build with GraphIndexBuilder and builder.addGraphNode(node, scores.searchProviderFor(node)), then write:
var writer = new OnDiskGraphIndexWriter.Builder(graph, path)
        .withVersion(7).with(new FusedASH(maxDegree, ash)).with(new NVQ(nvq)).build();

// Search: prepare the query once, then search with NVQ reranking.
var preparer = index.queryPreparer(VectorSimilarityFunction.DOT_PRODUCT).orElseThrow();
var prepared = preparer.newState();
preparer.prepare(query, prepared);
var result = searcher.search(view.scoreProviderFor(prepared, true), 10, 20, 0.0f, 0.0f, Bits.ALL);
```

Query projection precision is selected with `-Djvector.ash.queryProjection` (`auto`, the default,
or `fp32`, `fp16`, `int8`).

**Notes**

- **On-disk format version 7.** Fused ASH and serialized ASH models require format version 7,
  which this release introduces and which JVector 4.0.x cannot read. `CURRENT_VERSION` and the
  writer defaults are now 7. Hosts that must be able to roll back should keep passing
  `withVersion(6)` and `write(out, 6)` until every reader runs this release; version 6 and older
  files are written and read as before. See [UPGRADING.md](../../../UPGRADING.md).
- **Similarity.** ASH scores dot product only. Use `DOT_PRODUCT` with normalized vectors for
  cosine similarity.
- **Concurrency.** A prepared query, its searcher and its view belong to one in-flight search;
  reuse them only after it completes. For asynchronous serving, size execution to the physical
  cores allocated to search and use bounded admission; see
  [Integrating ASH queries into a database](../../ash-query-integration.md).
- **Adaptive termination.** Searches of a fused ASH index through a prepared query stop when
  further candidates are unlikely to improve the results (relative margin 0.01). Disable it with
  `GraphSearcher.useAdaptiveTermination(false)`.
- **BLAS threads.** JVector sets the native BLAS thread count for ASH training: one thread, or
  the size of the executor passed to `AsymmetricHashing.initialize`. Hosts no longer need
  `MKL_NUM_THREADS` to keep MKL or OpenBLAS from starting a thread per CPU.
- **Compaction.** `OnDiskGraphIndexCompactor` does not yet compact fused ASH indexes.
