### PQ Training No Longer Copies the Training Set to Center It

**Description**

`ProductQuantization.compute` and `refine` with `globallyCenter = true` subtracted the global centroid from
every training vector, building a second full-size copy of the training set that stayed alive for the whole
k-means run. They now subtract the matching centroid slice from each subvector as it is extracted for a
subspace. The values k-means sees are identical, the caller's vectors are never modified, and no centered copy
is allocated. See [#807](https://github.com/datastax/jvector/issues/807).

**How to Enable**

No configuration is required.

**Notes**

Training PQ with 256 subspaces and 256 clusters on 128,000 x 1024-dimension vectors needed between 1000 and
1200 MB of heap on the previous code and completed at 700 MB (the lowest tried) with this change, against a
524 MB training set. Encoding still allocates a short-lived centered vector for each encoded vector.
