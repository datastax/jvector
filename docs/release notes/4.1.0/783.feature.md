### GPU graph construction (optional `jvector-gpu` module)

**Description**
Graph indexes can now be built outside `GraphIndexBuilder`'s incremental insertion, through a new
`@Experimental` service interface, `GraphBuildAccelerator`. An accelerator computes every node's
diversity-pruned neighbour list (and the hierarchy's upper layers) its own way and hands the lists to
`GraphIndexBuilder.addGraphNodeWithNeighbors`; `cleanup()`, search, writers and the on-disk format are unchanged.

The new optional module `jvector-gpu` implements it for NVIDIA GPUs with [TornadoVM](https://github.com/beehive-lab/TornadoVM)
and NVIDIA cuVS: cuVS NN-Descent candidates, then diversity pruning with the builder's alpha on the GPU. It also
trains and encodes PQ (`GpuProductQuantization`, codes identical to JVector's with the same codebooks), encodes NVQ
(`GpuNvq`) and compacts on-disk segments by rebuilding (`GpuCompaction`). On an RTX 4090, building Wikipedia 1M x 1024
(Cohere embed-multilingual-v3) takes about 17 s against 182 s on a 32-thread CPU; recall@10 is higher from search beam 40 up and 0.005 lower at beam 20.

**How to Enable**
Nothing changes by default. The module is built with `mvn -Pgpu`; it needs JDK 22+, the TornadoVM 8.0.0 CUDA SDK and
cuVS (`jvector-gpu/cuvs-env.sh` installs it). Select it with `-Djvector.graph.accelerator=tornadovm`, or call
`GraphBuildAccelerators.find()` and `build(builder, vectors, similarity)` directly. `jvector-gpu/run.sh check` compares
every GPU path with JVector's CPU code. Without a GPU or TornadoVM, every entry point falls back to the CPU code.

**Notes**
CUDA (NVIDIA, compute capability 8.0+) only. COSINE, DOT_PRODUCT and EUCLIDEAN, any dimension, max degree up to 64.
Incremental insertion and deletes stay on the CPU path. See `jvector-gpu/README.md`.
