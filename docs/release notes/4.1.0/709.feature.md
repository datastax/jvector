### Native Int8 (Byte) Vector Support

**Description**
JVector can now build, store and search signed int8 vectors natively, without converting them to float32.
This is useful when an embedding model already emits int8 vectors, or when vectors have been scaled to
int8 up front: they take 4x less space on disk and in memory than float32, and all scoring is done
byte-by-byte.

* `RandomAccessByteVectorValues` (and `ListRandomAccessByteVectorValues`) provide random access to
  `ByteSequence` vectors. It and `RandomAccessVectorValues` now share a common `VectorValues<V>`
  interface, which also provides `getVectorInto(node, destination, offset)` for reading a
  vector into a caller-owned buffer.
* `ByteVectorSimilarityFunction` scores two int8 vectors: `EUCLIDEAN` is `1 / (1 + squaredL2)`,
  `DOT_PRODUCT` is `dot < 0 ? 1 / (1 - dot) : dot + 1`, and `COSINE` is `(1 + cosine) / 2`. The scores are
  not normalised by dimension, so distinct integer distances stay distinct at high dimensions.
  `DOT_PRODUCT` scores are positive but not bounded above by 1.
* `GraphIndexBuilder.builder(RandomAccessByteVectorValues, ByteVectorSimilarityFunction, M)` builds a graph
  from int8 vectors, and `GraphIndexBuilder.build(VectorValues<?>)` accepts either vector type.
* The `InlineByteVectors` on-disk feature (`FeatureId.INLINE_BYTE_VECTORS`) stores each vector as `dimension`
  raw bytes. `OnDiskGraphIndex.View.byteVectorRerankerFor(...)` scores candidates directly from disk, and
  `getByteVectorInto(...)` reads a vector into a reusable buffer.
* Int8 distance kernels (squared L2, dot product, cosine) are available in the default, Panama and native
  SIMD implementations, and accumulate in integers so all execution paths return identical results.
* `BenchYAML` and `AutoBenchYAML` support int8 datasets: mark a dataset with `is_int8: true` in
  `dataset-metadata.yml`. A runnable example is in `Int8Example` (`-Dtutorial=int8`).

**How to Enable**
No configuration is required; the float32 APIs are unchanged. To use int8 vectors, build with the byte-vector
builder and write the index with the `InlineByteVectors` feature:

```java
RandomAccessByteVectorValues vectors = new ListRandomAccessByteVectorValues(byteVectors, dimension);
try (var builder = GraphIndexBuilder.builder(vectors, ByteVectorSimilarityFunction.EUCLIDEAN, 32).build()) {
    var graph = builder.build(vectors);
    try (var writer = GraphIndexWriter.getBuilderFor(GraphIndexWriterTypes.RANDOM_ACCESS_PARALLEL, graph, path)
            .with(new InlineByteVectors(dimension)).build()) {
        writer.write(Map.of(FeatureId.INLINE_BYTE_VECTORS, n -> new InlineByteVectors.State(vectors.getVector(n))));
    }
}
```

**Notes**
* The new interfaces and classes are marked `@Experimental` and the API may change in later releases.
* Only signed int8 (-128..127) is supported. Unsigned uint8 data, such as conventional SIFT1B/BIGANN `.bvecs`
  files, must be converted first; it is not detected, and reading it as signed silently changes distances.
* Quantization and compression (PQ, BQ, NVQ, fused graphs) are not supported for int8 vectors. Traversal
  already scores exactly, so a separate reranking step is not needed. `rerankK` still controls how much of the
  graph is searched.
* Zero vectors are not supported with `COSINE` (the result is undefined); do not index them.
* Existing float32 callers keep working: `RandomAccessVectorValues.getVector` keeps its `VectorFloat<?>`
  signature and `GraphIndexBuilder.build(RandomAccessVectorValues)` is retained as a forwarding overload.
* Int8 indexes require on-disk format version 6 or later.
