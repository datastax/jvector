### Compaction: sharded compaction sessions and a choice of output format version

**Description**

JVector 4.0.2 made `OnDiskGraphIndexCompactor` find level-0 neighbours by scanning cells instead of
searching ([#740](https://github.com/datastax/jvector/pull/740)). This change builds on it in three ways.

- **Sharded compaction sessions.** A host that splits a merge into several outputs (Cassandra writes
  one sstable per token range) previously ran one compaction per output. Each run trained the
  codebooks again, and each lost recall: a shard keeps only a small part of every source, so a node
  kept few of its same-source edges and nothing replaced them. A session trains the codebooks once,
  on the live nodes of every shard, and shares them. In each shard it also searches a source with
  fewer than half its nodes live for the node's own neighbours. Ordinary `compact` calls are
  unchanged.
- **`withVersion(int)`** writes the output at any on-disk format version the writer supports instead
  of only `OnDiskGraphIndex.CURRENT_VERSION`. Sources may be at different versions. A version that
  cannot hold the output is rejected: fused PQ needs 6, and upper layers need 4 or above.
- **Faster merges larger than memory.** The cell walk sizes its ranges from the heap and from what it
  measures, announces source records to the page cache ahead of reading them, frees its tables
  before writing the upper layers, and reads the merge store with direct I/O when the store does not
  fit in memory beside the heap.

tessera-2M, two 1M-vector sources (1024 dimensions, cosine, degree 32) merged into hash shards, 8 cores. Each
cell shows total time and recall@10:

| Shards | One compaction per shard | One session | Rebuild of every shard |
|---|---|---|---|
| 4 | 454 s, 0.781 | 566 s, 0.825 | 876 s, 0.836 |
| 16 | 981 s, 0.823 | 567 s, 0.894 | 946 s, 0.903 |
| 64 | 1203 s, 0.875 | 627 s, 0.945 | 886 s, 0.947 |

**How to Enable**

Open a session on a compactor built with the live nodes of every shard, then merge each shard:

```java
var compactor = new OnDiskGraphIndexCompactor(sources, liveNodes, VectorSimilarityFunction.COSINE, null);
var session = compactor.sharded();
List<OrdinalMapper> shard0 = session.compactShard(shard0LiveNodes, output0);
List<OrdinalMapper> shard1 = session.compactShard(shard1LiveNodes, output1);
```

Sources with a compressed sidecar use `compactShard(shardLiveNodes, graphPath, compressedPath)`.
To choose the output's format version, call `compactor.withVersion(6)` before compacting; a session
writes every shard at its compactor's version. The large-merge changes need no configuration.

**Notes**

- `sharded()`, `compactShard` and `withVersion` are `@Experimental`. A session is not thread-safe:
  shards are compacted one at a time, and may become known one at a time.
- At 4 shards the same-source search costs more time than shared training saves; from 16 shards
  the session is faster and its recall is within a point of a rebuild.
- A merge whose top levels have no live node, which a shard can produce, now ends its hierarchy at
  the highest level that still has one instead of failing.
- Record announce-ahead is asynchronous (`POSIX_MADV_WILLNEED`) only with the `jvector-native`
  reader. Other readers fall back to their synchronous `prefetch`.
- See [compaction](../../compaction.md) for details.
