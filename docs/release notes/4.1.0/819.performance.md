### Faster Exact-Score Search and Graph Construction

**Description**

A search expanding a node used to score its unvisited neighbors one at a time, so each neighbor's vector was
loaded only after the previous score was finished. The views now score them with one bulk call, and the Panama
provider scores four vectors per pass, which keeps four vectors' memory loads in flight. Diversity pruning during
construction scores the selected neighbors the same way. Each target accumulates exactly as the pairwise kernel
does, so scores, search results and built graphs are unchanged. See
[#818](https://github.com/datastax/jvector/issues/818).

New API: `VectorSimilarityFunction.compare(q, targets, count, results)`, the matching bulk methods on `VectorUtil`
and `VectorUtilSupport`, and `ScoreFunction.similarityTo(int[] nodes, int count, float[] results)`.

**How to Enable**

No configuration is required for `DefaultSearchScoreProvider.exact` and `BuildScoreProvider.randomAccessScoreProvider`.
A custom `ExactScoreFunction` benefits once it implements the bulk `similarityTo`, for example by fetching the vectors
and calling `VectorSimilarityFunction.compare(q, targets, count, results)`.

**Notes**

On an AVX-512 Xeon with 100,000 1024-dimension COSINE vectors, single-threaded exact search went from about 1,230 to
about 1,680 queries per second on the same graph, and building the graph took 19.5 s instead of 24 s (20.5 s
instead of 28 s on AVX2). The native provider
still scores pairwise with its own kernels.
