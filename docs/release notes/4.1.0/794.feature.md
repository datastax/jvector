### GPU compaction, PQ and NVQ encoding (optional `jvector-gpu` module)

**Description**
Builds on the GPU graph construction of #783. `GpuCompaction` merges on-disk segments by rebuilding the merged
graph on the GPU; it takes the same inputs as `OnDiskGraphIndexCompactor` and gives the new ordinals through
`ordinalMappers()`. `GpuProductQuantization` trains and encodes PQ the way `ProductQuantization` does (codes identical
with the same codebooks), and `GpuNvq` encodes NVQ. On an RTX 4090 against a 32-thread i9-13900K (ada002-1M):
compaction of 4 segments 16.0 s against 226.4 s, PQ 2.6 s against 15.8 s, NVQ 1.3 s against 4.0 s.

**How to Enable**
Build with `mvn -Pgpu` (JDK 22+, the TornadoVM 8.1.0 CUDA SDK, cuVS via `jvector-gpu/cuvs-env.sh`) and call
`GpuCompaction.compact`, `GpuProductQuantization.compute`/`encodeAll` or `GpuNvq.encodeAll`. `jvector-gpu/run.sh check`
compares them with JVector's CPU code.

**Notes**
The GPU compaction is in-core. `compact()` decides from the sizes before it reads any vector, and merges anything
that does not fit in host or device memory with `OnDiskGraphIndexCompactor`, as it does without a GPU or TornadoVM.
CUDA (NVIDIA, compute capability 8.0+) only. See `jvector-gpu/README.md`.
